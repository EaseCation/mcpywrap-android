# 产品实现架构

## 模块

| 模块 | 职责 |
| --- | --- |
| `app` | Android 入口、权限与 manifest、各模块装配、集成测试 |
| `core:designsystem` | 官方 Compose Material 3 1.4.0、明暗主题 |
| `core:model` | 公共目录常量、原样打包的普通模板；不含原型状态机 |
| `core:engineering` | 发布版 mcpywrap-core、独立核心工作进程、版本安装与回滚；工程调用使用共享 Python API |
| `core:application` | UI 与 HTTP 共用的工程/游戏操作、互斥锁、启动恢复与诊断 |
| `core:bridge` | 回环 HTTP/WebSocket、工作区授权、幂等任务与用户主动开启的前台服务 |
| `core:workspace` | 公共磁盘仓库、原子保存、草稿、冲突检测、导入、快照、世界与回收站 |
| `feature:editor` | Sora + TextMate 编辑器；不执行 Python、不生成业务源码 |
| `feature:studio` | Compose 界面、不可变状态 / StateFlow / ViewModel、异步操作编排 |
| `runtime-core` | WorkManager 前台安装任务、断点下载、签名/摘要校验、安装回执 |
| `game-host` | Android 生命周期、JNI 桥、源码 importer、世界启动/保存退出、真实 PiP |
| `game-plugin` | 独立 dex 的自有适配 APK，隔离游戏与编辑器 AndroidX |
| `engine-contract` | 只参与编译的 ABI 声明，不打包成游戏实现 |

## 数据与生命周期

`/sdcard/mcpy/projects/<名称>` 是项目的唯一权威文件位置。外部编辑器与内部编辑器操作这些文件。每次打开文件记录 SHA-256；保存前比对，冲突时保留草稿并拒绝覆盖。未保存草稿写入公共 `build/drafts`，再次打开对应文件可以恢复。

运行前由工程核心读取公开项目配置、解析本地依赖并组装。Android 把组装结果复制为完整快照，按内容摘要放进 `mods/<项目ID>/<摘要>`，再为所选世界部署行为包和资源包。正在运行的游戏使用该世界自己的部署目录，编辑项目不会改变它。世界、原生引擎所需目录、`minecraftWorlds/local-world` 均位于 `worlds/<作品名>/<实例名>` 下；不把世界复制到私有目录运行。

启动配置、源码 importer、运行状态、真实引擎返回值与错误日志位于 `logs/session-*`。状态回执定时更新；旧心跳显示为中断，另检查同 UID 游戏进程是否仍存活以避免错误重启。应用修改前等待引擎确认退出世界，再创建新会话。不以窗口存在或 UI 定时器声称游戏已执行。

环境安装由唯一 WorkManager 任务负责，任务在离开编辑器页面后继续。取消保留分段；安装互斥锁阻止暂停后的旧请求与续传任务同时写文件。校验包括固定 APK SHA-256、包名、签名证书以及分段摘要。原生库与 dex 只从确认版本加载。未校验完成时没有安装回执，UI 不启用启动。

游戏通过独立 `:game` 进程与类加载器运行。类加载父级使用平台 loader，避免编辑器的 AndroidX 覆盖官方游戏的实现；自有 adapter APK 与官方下载的 APK 同处专用 loader。运行世界和 Mod 不放在 dex 缓存里。

## 与 mcpy 的边界

Android 负责文件管理、组件输入布局整理、游戏环境安装、实例部署与 Android 生命周期。依赖解析、资源合并、构建、打包由内置的发布版 `mcpywrap-core==0.6.2` 负责。运行和导出不再直接扫描源工程后跳过依赖处理。

`core:engineering` 使用 Chaquopy 17.1.0 / CPython 3.13，运行在不导出的 `:core` Service。`EngineeringClient` 在 App 内串行调度；每个有限请求使用新工作进程，返回结果后等待 Binder 死亡再接受下一请求，避免升级时混合 Python 模块。界面与 `:game` 进程不载入工具 Python。

普通组件首次构建时会新增标准 `pyproject.toml`，源码保持原样；已有 TOML 不改写。构建结果位于配置的作品内子目录或 `/sdcard/mcpy/build`；分发 ZIP 由共享核心生成，再保存到 `/sdcard/mcpy/exports`。导入普通单包/双包时只规范行为包和资源包目录名称；已有工程保留其结构。

支持 Addon、本地组件与通过已配对开发端准备的 Git/pip 依赖。Git URL 导入由 JGit 完成；工程依赖获取、构建 hooks 和消费者准备由共享核心发出分阶段计划，开发端执行工具阶段并交回结果，App 核心校验后继续组装。缺少准备能力时明确要求使用开发端，不跳过或回退到另一套组装规则。地图工程尚未接入。

工程核心更新从固定 HTTPS PyPI 元数据获得版本、下载地址和 SHA-256，只接受 `files.pythonhosted.org` 的纯 Python wheel。共享 `CoreStore` 校验版本/API/基础依赖/路径/摘要后执行真实构建健康检查，成功才切换。失败保留原版。核心版本和协调锁属于可重建的私有工具环境，项目与输出始终留在公共目录。更新信任基于固定 PyPI HTTPS 来源，不宣称额外实现了发布者签名链。

每次任务日志位于 `/sdcard/mcpy/logs/engineering-*.log`。工程核心使用内部 Binder 接入；外部工具通过经授权的回环 HTTP/WS 服务调用同一应用服务。任务和准备阶段回执持久保存，系统结束服务后的未完成任务报告中断，不自动重放修改操作。详细协议见[本机开发接口](local-host-api.md)。

游戏中的 Python 仍来自官方运行内核，与工具 CPython 完全分离。设置中的“工程核心”更新不升级游戏内核、不停止运行中的游戏，也不要求重新安装 APK。

## 画中画生命周期

已对下载 APK 反射核对 `GameActivity.onPauseNative(long)` 为 protected、非 final 的虚方法。适配层在 PiP 可见期间延后该原生暂停回调，并保持引擎窗口焦点；Android Activity 的 onPause 生命周期仍正常执行。退出 PiP 后恢复正常暂停处理，onStop/onDestroy 没有被跳过。验收同时检查系统 PiP 标记、引擎 HUD、编辑器运行状态和保存退出，不靠窗口截图猜测运行状态。

PiP 缩放保留进入小窗前的 Surface 缓冲区尺寸（SurfaceHolder.setFixedSize），由 SurfaceView 将完整帧缩放到窗口。退出 PiP 后恢复 setSizeFromLayout。不能只缩小窗口而让游戏继续向较小缓冲区按原始 viewport 绘制，否则会裁切为左下角。

缩放期间还锁定传给游戏内核的 Configuration 和 content rect，使游戏的逻辑视口与固定缓冲区一致。Android 窗口布局照常变小，游戏自身不按小窗宽度重排物品栏；全屏布局恢复后解除锁定。

## 作品下的实例

实例通过稳定 projectId 固定归属，创建/查询/运行/备份/删除都需要作品上下文。不存在先创建全局世界再选择作品的入口；再次测试实例会应用当前作品代码，revision 只是上次运行的记录。

作品内的“测试实例”页负责新建、测试、备份和删除。删除使用回收站；运行中的实例不可移动。删除作品时源码和该作品的实例组一并移入同一回收记录，恢复也一起完成。

旧版有明确关联的世界迁移到作品目录组，并保留实例 ID 与存档。新实例按创建时间排序；旧版缺少创建时间时，以原元数据时间作为排序依据。正在运行时延后移动。无归属旧世界保留在原位置，仅通过作品内的恢复入口认领；后续不允许换绑。文件冲突拒绝覆盖。

## 等待呈现与读取状态

StudioViewModel 区分非模态阶段提示和提交阶段的模态等待。工作区加载状态与数据快照分离，不能把初始空集合当成读取成功；空态只在成功读取后显示。刷新保留已有数据。读取和预览取消时等待核心工作进程退出，再接收下一任务。

编辑器语法库在 IO 线程初始化，未完成时显示原位进度/错误重试。核心任务通过 Binder 上报阶段，安装任务使用 WorkManager 进度与系统通知。游戏宿主的 loadingStage 由真实启动步骤及 HUD 回执决定，不用计时器伪造成功或百分比。

工作区及核心版本读取属于跨标签页共享任务，切换作品/设置不取消它。页面专属文件读取、结构预览可以取消；解绑前先清除连接所有权，避免取消后排队的最终回复二次解绑服务。取消后仍等待旧核心进程退出，再接收新请求。

游戏浮窗入口由独立的 `FloatingPipButton` 平台控件实现，图标表达画面缩小，点击调用既有 PiP 流程。拖动只更新控件位置，按系统 touch slop 区分点击，贴边位置按比例保存在私有工具偏好中；不修改游戏 Surface 或渲染缓冲区。PiP 隐藏入口，全屏恢复后依据窗口安全区域重新定位。

按钮移动使用真实布局边距，并请求窗口重新计算透明区域；不能仅更新 translation，否则游戏 Surface 上方的按钮可能在拖动后被错误裁去。覆盖测试同时检查触摸、位置、画面中实际绘制的图标、再次进入全屏以及完整缓冲区尺寸。
